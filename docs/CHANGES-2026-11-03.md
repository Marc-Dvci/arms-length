# Code audit fixes — 3 November 2026

The local source now enforces Jira administrator permission for settings and pairing, the current user's Browse
and Edit permissions for issue actions, and Add Comments for management responses. Population results contain
only issues the caller can read. Bitbucket pairing checks the current workspace administrator; PR cards and
rechecks verify the current user's access before fetching app-held evidence.

Evidence arrays use a versioned `record` custom entity with conditional transactions. The transaction updates
the legacy key/value projection too, so prefix discovery continues to work. Existing arrays migrate on their
next write. Deploy the Jira manifest containing this entity before running the new backend.

The Bitbucket app sends full `workspace/repository` identities and canonical post-merge snapshots. Its updated
manifest adds PR change triggers and `read:workspace:bitbucket`; existing installations must grant that scope.
Older snapshots cannot replace newer revisions. Conflicting snapshots with identical source and observation
times mark the evidence incomplete until a fresh observation resolves the ambiguity.

The release gate requires one complete, merged PR identified by the full repository and full commit hash.
Only its final head or merge commit is eligible. It evaluates the proposed deployment before recording it.
The pipeline script reads `BITBUCKET_REPO_FULL_NAME` (or workspace plus repository slug); custom runners must
provide those variables and a full commit. Update every copied gate script, including the example payments
repository. After a merge, allow the PR event to arrive; an early pipeline attempt fails closed and can be retried
or refreshed through the PR card. Legacy snapshots remain available for viewing but cannot authorize release
until refreshed with a full repository identity.

Exception creation takes a conditional claim before calling Jira. Concurrent callers share the result. A lost
response is recovered by a unique Jira label; an ambiguous server failure retains the claim to avoid duplicates.
Explicit client rejections permit a new attempt after the configuration or permission problem is corrected.

Use Node 24.22.1 and run `npm ci`, `npm run audit`, and `npm audit --audit-level=low`. The shell tests now execute
under Git Bash on Windows and POSIX shells on Linux. `ARMS_LENGTH_TEST_SHELL` can choose a specific shell.

These changes require deployment and installation upgrades. Local manifest validation and API mocks do not
establish that the installed Forge apps have been upgraded. Production MCP tool exposure remains an Atlassian
administration/platform prerequisite; see the workspace change report for the recorded error and follow-up.
